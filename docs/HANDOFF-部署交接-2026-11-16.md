### 10.5 关于 OBS 内网与阿里云解析（运维结论）

- 域名解析放在阿里云**不影响 OBS 内网流量**。OBS 的域名是华为云自己的 `obs.cn-north-9.myhuaweicloud.com`，由华为云内网 DNS 解析，与 `barenkeji.com` 的 NS 无关。

- 结论：只要 ECS 与桶**同 region**（cn-north-9）且 endpoint 保持 `obs.<region>.myhuaweicloud.com`，服务器读写 OBS 就走内网，不消耗 EIP 带宽。
- 会走公网的两种情况：① 桶绑了自定义域名让浏览器直连；② endpoint 被改成公网加速域名/跨 region。
- **注意当前架构成交流量仍过 ECS**：预览图、ZIP 下载都是 API 从 OBS（内网）读出来再转发给客户端，出方向吃 ECS 带宽。将来量上来可改预签名 URL 直连 OBS。

### 11.1 部署脚本

```bash
./scripts/deploy.sh                 # 全流程：推 GitHub -> 同步源码 -> 依赖 -> 迁移 -> 构建 -> 重启 -> 健康检查
./scripts/deploy.sh --restart-only  # 只重启（不推、不同步、不构建）
./scripts/deploy.sh --dry-run       # 只列 rsync 差异
./scripts/deploy.sh --skip-git      # 跳过 GitHub 推送（网络不通时）
```

执行顺序（**本地只推源码，产物在服务器构建**，避免 macOS↔Linux 原生模块与 esbuild 平台差异）：

1. `git add -A` + 自动提交（有改动才提交）→ `git push <remote> HEAD:<branch>`
   - 默认 `origin`，分支默认跟随上游（`origin/main` → `main`）
   - 覆盖：`PROOFROOM_GIT_REMOTE` / `PROOFROOM_GIT_BRANCH`
   - 推送失败即中止，不会出现"服务器已更新但 GitHub 没版本"的状态
2. `rsync -az --delete --checksum`（排除 `node_modules .next-* dist logs .git .env .local .deploy-backup`）
3. 服务器 `scripts/deploy-remote.sh`：预检 → `npm ci`（lock 变更才装）→ 迁移 → 备份旧产物到 `.deploy-backup/<STAMP>/`（留 5 份）→ 构建 api/worker → web 构建到 `.next-new` 再原子切换 → 重启三服务 → 健康检查（api / web / 公网）

实跑耗时 20-24s，日志 `/mnt/sdc/proofroom/logs/deploy-<STAMP>.log`。

**踩过的坑**：`rsync --delete` 一开始把服务器 `.deploy-backup/` 的旧备份一起删了（本地没有该目录 → 视为多余文件），回滚能力形同虚设。已在排除列表加 `.deploy-backup`，**不要删这一项**。
